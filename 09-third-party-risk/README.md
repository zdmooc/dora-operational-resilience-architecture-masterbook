# I9 — ICT Third-Party Risk

## FR

DORA rend explicite une réalité : une institution reste responsable de sa résilience même lorsqu'elle utilise des fournisseurs ICT.

### Lifecycle

```text
Need
→ Criticality assessment
→ Risk assessment
→ Due diligence
→ Architecture review
→ Contract
→ Onboarding
→ Monitoring
→ Change/Subcontractor review
→ Incident/Testing
→ Exit
```

### À cartographier

- provider;
- ICT service;
- supported function;
- hosting locations;
- data locations;
- subcontractors;
- dependencies;
- SLA/SLO;
- security controls;
- recovery;
- audit/access rights;
- portability;
- exit.

### Concentration risk

Analyser :
- provider concentration;
- geographic concentration;
- technology concentration;
- shared control plane;
- common subcontractor;
- common network/carrier;
- common IAM/PKI.

## EN

Third-party risk must be treated as an architecture dependency problem, not only a procurement questionnaire.

### Deliverables

- Third-Party Dependency Map;
- Provider Criticality Matrix;
- Subcontractor Chain;
- Concentration Heatmap;
- Alternative/Fallback Analysis;
- Exit Feasibility Assessment.

## 2026 extension

EBA third-party risk guidelines published on 18 September 2026 broaden the lifecycle view beyond ICT-only arrangements and reinforce due diligence, contracting, monitoring, subcontracting and exit-strategy thinking.
