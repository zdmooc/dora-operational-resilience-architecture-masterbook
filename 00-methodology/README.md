# I0 — Méthode / Method

## FR — Comment étudier DORA comme architecte

Ne pas mémoriser le règlement article par article. Utiliser quatre couches :

```text
1. Obligation réglementaire
2. Capacité organisationnelle
3. Capacité d'architecture
4. Preuve / evidence
```

Exemple :
- obligation : gérer le risque ICT ;
- capability : ICT risk management ;
- architecture : inventaire, dépendances, controls, observability, recovery ;
- evidence : registre, ADR, tests, métriques, incidents, runbooks.

## EN — How to study DORA as an architect

Do not study DORA as a list of legal articles. Translate every requirement into:
- governance capability;
- architecture capability;
- operational control;
- evidence.

## Méthode de lecture / Reading method

Pour chaque sujet / For each topic:
1. **What does the regulation require?**
2. **What decision does an architect make?**
3. **What information must be discovered?**
4. **What artefact proves the reasoning?**
5. **What cannot be inferred without client context?**

## Niveaux de preuve / Evidence levels

- REFERENCE_DESIGN
- DOCUMENTED
- IMPLEMENTED
- TESTED
- RUNTIME_PROVEN
- AUDITED
- REGULATORY_COMPLIANCE — jamais revendiqué par ce dépôt / never claimed by this repository.
